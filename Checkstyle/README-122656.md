# Checkstyle — Aluno 122656

## Regra escolhida

Foi configurada a regra `MethodName` do Checkstyle, que verifica a convenção de nomes dos métodos Java.

A expressão regular utilizada foi:

`^[a-z][a-zA-Z0-9]*$`

Esta regra exige que os nomes dos métodos comecem por uma letra minúscula e contenham apenas letras e números, seguindo a convenção camelCase.

## Integração contínua

Foi criado o workflow `.github/workflows/checkstyle.yml`, que executa o Checkstyle automaticamente nos Pull Requests destinados à branch `main`.

O workflow utiliza Java 21 e termina com erro quando encontra violações da regra configurada.

## Limitações

A regra `MethodName` verifica apenas a estrutura dos nomes dos métodos, não avaliando se os nomes são claros ou descrevem corretamente a sua funcionalidade.

Além disso, a configuração atual não verifica outras convenções de nomes, como as de classes, variáveis ou constantes.

O workflow analisa apenas os ficheiros Java localizados em `src/main/java`, pelo que métodos presentes noutros diretórios não são abrangidos.

## GitHub Marketplace Action

O workflow utiliza a GitHub Marketplace Action
`dbelyaev/action-checkstyle@v4`, configurada com o ficheiro
`Checkstyle/checkstyle.xml`.

A Action foi integrada na branch `main` através de um Pull Request,
após a verificação Checkstyle ter terminado com sucesso.

## Proteção da branch main

Foi criada uma ruleset ativa denominada `Checkstyle - Proteção da main`,
aplicada à branch `main`.

A ruleset exige um Pull Request e a aprovação automática da verificação
`checkstyle` antes de permitir a integração de alterações.

As verificações Maven, Qodana e SonarCloud não foram definidas como
obrigatórias nesta ruleset.
